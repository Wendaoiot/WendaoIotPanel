# demo_rs485 —— RS485 数据采集上报示例

Air780EPM（LuatOS）通过 4G 连接 wendaoiot 平台，演示 **RS485 串口收发**：设备每 2 秒发送一帧 ASCII 测试串验证发送方向；485 总线上收到的数据上传平台；平台下发的数据写到 485 总线。

> 本示例是**透明 ASCII 收发验证**（不含 Modbus 协议），用于最快验证 RS485 硬件链路和平台链路是否正常。接入 Modbus 仪表时，在 `rs485_app.lua` 基础上加主站请求/CRC/解析即可，硬件方向控制无需改动。

## 功能与数据流

```
USB转485/485设备  ──A/B总线──►  收发器  ──►  UART2 ──MQTT──► wendao/<IMEI>/rs485/up
        ▲                                                              │
        └────────────────  UART2 ◄── wendao/<IMEI>/rs485/down ◄──────平台
设备每 2 秒主动发送：rs485 test #N, imei=xxxx
```

## 文件说明

| 文件 | 作用 |
|---|---|
| `main.lua` | 程序入口：板载电源/看门狗初始化，加载模块 |
| `mqtt_wendao.lua` | wendaoiot 平台连接（通用文件，不用改） |
| `rs485_app.lua` | RS485 收发业务（串口号、方向脚、主题后缀在文件顶部） |

## 硬件接线（38盒子 V3.1）

| 38盒子端子 | USB转485 | 说明 |
|---|---|---|
| 485-A | A（或 485+） | **A 接 A** |
| 485-B | B（或 485-） | **B 接 B**（收不到数据先对调 A/B 试试） |
| GND | GND | 建议共地，提升抗干扰 |

板载电路：RS485 收发器由 **EN1（GPIO37）使能的 RS485_5V** 供电（`main.lua` 已拉高）；方向脚 **GPIO33（485_DIR）** 接收发器 DE/nRE，由固件在 `uart.write` 时自动控制。

串行参数：**9600 波特率、8 数据位、1 停止位、无校验**。

## 烧录步骤

1. Luatools 用 USB 连接 38盒子，选择固件 **LuatOS-SoC V2024 Air780EPM**（仓库 `core/LuatOS-SoC_V2024_Air780EPM/`，建议 `106` 版）。
2. 添加本工程目录（`demo_rs485`）为脚本，下载。
3. 上电日志记录设备 `IMEI`。

## 平台说明

默认 Broker `panel.wendaoiot.com:1883`，主题 `wendao/<IMEI>/<功能>`，设备身份 = IMEI。
接自己平台改 `mqtt_wendao.lua` 顶部配置区 3 个常量（`HOST` / `PORT` / `TOPIC_PREFIX`）。

## 上位机验证（MQTTX + 串口助手，三步）

1. USB转485 接好 A/B，串口助手选该串口、**9600 8N1** 打开；MQTTX 连接 `panel.wendaoiot.com:1883`。
2. **验设备发送**：串口助手应每 2 秒收到一行 `rs485 test #1, imei=...`（说明模组 485 发送正常）。
3. **验设备接收 + 平台上行**：串口助手发送任意字符串（如 `hello`）→ MQTTX 订阅 `wendao/+/rs485/up` 应收到该内容。
4. **验平台下行**：MQTTX 向 `wendao/<本设备IMEI>/rs485/down` 发布字符串 → 串口助手应收到该内容。

## 常见问题

- **串口助手收不到测试串**：检查 EN1(GPIO37) 是否拉高（用本工程 `main.lua` 即已配置）；A/B 对调试试；确认串口助手波特率 9600、COM 口正确。
- **只能发不能收（或反之）**：多为方向脚/接线问题。本工程用 LuatOS 硬件自动方向（GPIO33），若自研板方向逻辑相反，把 `rs485_app.lua` 里 `RS485_RX_DIR_LEVEL` 改为 `1`。
- **接 Modbus 仪表**：把周期测试串任务换成 Modbus 请求帧（功能码 03/04 + CRC16），在接收回调里解析寄存器即可，`uart.setup` 的 485 方向参数保持不变。
